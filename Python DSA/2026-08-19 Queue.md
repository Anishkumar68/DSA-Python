# Queue 

## 1. The Theory 
A **Queue** is a linear data structure, but unlike a Stack (which only has one "Top"), a Queue has **two distinct ends**:
1. **Front:** The end where items are removed.
2. **Rear (or Back):** The end where items are added.

* **The Golden Rule:** **FIFO** (First-In, First-Out). The first element you put into the queue is the first one you take out.
* **Time Complexity:** Just like the Stack, adding and removing should take **O(1)** time. *(Note: Achieving O(1) requires a smart implementation, which we will cover when we write the code!)*

### 2. Core Operations 
Because we have two ends, our vocabulary changes slightly. We use these 4 basic operations:

1. **`enqueue(item)`**: Adds an item to the **Rear** of the queue. *(Think of it as "getting in line")*.
2. **`dequeue()`**: Removes and returns the item at the **Front** of the queue. *(Think of it as "being served and leaving")*.
3. **`peek()` or `front()`**: Returns the item at the **Front** *without* removing it. (Just seeing who is next in line).
4. **`is_empty()`**: Returns `True` if the queue has no elements, `False` otherwise.

### 4. Step-by-Step Visualization
Let’s trace the logic. Imagine an empty queue. We will track the **Front** and the **Rear**.

| Action | Queue State (Front -> Rear) | What happened? |
| :--- | :--- | :--- |
| **Start** | `[ ]` | Queue is empty. |
| `enqueue(10)` | `[10]` | 10 is both Front and Rear. |
| `enqueue(20)` | `[10, 20]` | 20 goes to the Rear. 10 is still Front. |
| `enqueue(30)` | `[10, 20, 30]` | 30 goes to the Rear. |
| `peek()` | `[10, 20, 30]` | Returns **10** (the Front). Queue doesn't change. |
| `dequeue()` | `[20, 30]` | Removes **10** from the Front. 20 is now Front. |
| `dequeue()` | `[30]` | Removes **20** from the Front. 30 is now Front *and* Rear. |

### 5. Why do we care? (Real-World Applications)
Queues are everywhere in computing when we need to handle things **in order**:
* **Printer Queues:** If 5 people send a document to the printer at the same time, the printer uses a queue to print them one by one in the exact order they arrived.
* **CPU Task Scheduling:** Your computer's processor has hundreds of tasks to do. It puts them in a queue and processes them one at a time so no task gets left behind.
* **Customer Support:** When you call a bank and hear *"Your call is important to us, you are number 4 in line,"* you are literally in a digital Queue!
