### 2. The Theory (Short but Detailed)
A **Hash Map** (also called a Hash Table, or a Dictionary in Python) is a data structure that stores data in **Key-Value pairs**.

* **The Golden Rule:** We want to find, add, or delete data in **O(1)** time (instantly), without searching through the whole structure.
* **The Magic Ingredient:** **The Hash Function**. This is a mathematical function that takes any Key (a string, a number, an object) and converts it into an **integer** (an array index). 

**The Formula:**
`Index = Hash_Function(Key) % Array_Size`
*(The modulo `%` ensures the index fits inside our underlying array).*

### 3. Core Operations (The Vocabulary)
1. **`put(key, value)`** or **`insert`**: Calculates the index for the key, and stores the value there.
2. **`get(key)`**: Calculates the index for the key, and returns the value stored there.
3. **`remove(key)`**: Calculates the index, and deletes the key-value pair.

---

### 4. Step-by-Step Visualization
Let’s build a tiny Hash Map. 
* Our underlying array has a size of **5** (indexes 0 to 4).
* Our simple Hash Function is: `Length of the string % 5`.

| Action            | Key    | Hash Math (`len % 5`) | Index | Array State (Index: Value) |
| :---------------- | :----- | :-------------------- | :---- | :------------------------- |
| `put("cat", 10)`  | "cat"  | 3 % 5                 | **3** | `[ _, _, _, 10, _ ]`       |
| `put("dog", 20)`  | "dog"  | 3 % 5                 | **3** | *Uh oh! Collision!*        |
| `put("bird", 30)` | "bird" | 4 % 5                 | **4** | `[ _, _, _, 10, 30 ]`      |

Wait, look at **"cat"** and **"dog"**. Both have 3 letters. Both get pushed to Index 3. This brings us to the biggest challenge in Hash Maps...

### 5. The Elephant in the Room: Collisions
A **Collision** happens when the Hash Function assigns the *same index* to two *different keys*. (Like "cat" and "dog" in our example). 

How do we fix it? There are two main strategies:
1. **Chaining (Most Common):** At Index 3, instead of storing just one value, we store a **Linked List**. So Index 3 becomes: `Head -> ("cat", 10) -> ("dog", 20)`. When we `get("dog")`, we go to Index 3, walk down the tiny linked list, and grab the right one.
2. **Open Addressing:** If Index 3 is full, we just look at Index 4. If 4 is full, we look at 5, until we find an empty slot.

### 6. Complexity Analysis (The Interview Cheat Sheet)

| Operation | Average Case | Worst Case | Why? |
| :--- | :--- | :--- | :--- |
| `get()` / `put()` / `remove()` | **O(1)** | **O(N)** | Average is instant. Worst case happens if *every* key collides and creates a massive Linked List at one index. |
| **Space** | **O(N)** | **O(N)** | We need an underlying array and nodes to store the N items. |

*Instructor Note: A good Hash Function and a properly sized array keep us in the O(1) Average Case 99% of the time!*

---

### 7. Why do we care? (Real-World Applications)
Hash Maps are the backbone of modern software. 
* **Caching:** Storing recently used data so you don't have to recalculate it (e.g., YouTube storing video thumbnails).
* **Counting Frequencies:** Counting how many times each word appears in a book.
* **Finding Duplicates:** Checking if an item exists in a massive list instantly.
* **Database Indexing:** Finding a user's profile in a database of 1 billion users without scanning every row.

There are exactly **two main families** of collision resolution. Let’s break them down using a very simple analogy: **A Parking Lot.**

---

### Type 1: Separate Chaining (The "Backpack" Method)

_This is what we just built in our code._

- **The Logic:** If parking spot `#5` is taken, we don't care. We just allow **multiple cars** to park in spot `#5`. But to keep them from crashing into each other, every car in spot `#5` gets its own little "backpack" (a Linked List) to hold them.
- **Pros:** The parking lot never gets "full" (we can always add another item to the list). Deletion is easy.
- **Cons:** Uses extra memory for the pointers (the backpacks/linked lists).

---

### Type 2: Open Addressing (The "Parking Lot" Method)

_This is the other major family. Here, **every spot in the array can only hold ONE item.** No backpacks, no linked lists._

- **The Logic:** If your designated parking spot `#5` is already taken, you cannot park there. You must drive down the lot and find the **next completely empty spot** (like `#6` or `#7`).

There are **three ways** to search for that empty spot:

#### A. Linear Probing (The "Next Door" Method)

- **The Logic:** If spot `#5` is taken, check `#6`. If `#6` is taken, check `#7`. You just step forward by **1** each time until you find an empty space.
- **The Flaw (Primary Clustering):** If spots 5, 6, and 7 are full, the next person who hashes to 5 has to walk past all of them. Soon, you get massive traffic jams (clusters) of full spots, making the lookup very slow.

#### B. Quadratic Probing (The "Jumping" Method)

- **The Logic:** To fix the traffic jam of Linear Probing, we change how we jump. If spot `#5` is taken, we jump **1** spot to `#6`. If that's taken, we jump **4** spots to `#10`. If that's taken, we jump **9** spots to `#19`. (We jump by 1212, then 2222, then 3232).
- **The Benefit:** This scatters the cars much further apart, preventing those massive traffic jams (clustering).

#### C. Double Hashing (The "Second Opinion" Method)

- **The Logic:** This is the most advanced and effective. If spot `#5` is taken, we don't just step by 1 or 4. We run the key through a **second, completely different math formula** to decide how many spots to jump.
    - _Example:_ Key A hashes to 5. Spot 5 is full. The _second_ formula says "jump by 3". We check spot 8. If 8 is full, we jump by 3 again to spot 11.
- **The Benefit:** It completely eliminates clustering because every key has its own unique "jump size".

| Collision Type        | How it handles a full spot                            | Best feature                                      | Worst feature                                                  |
| --------------------- | ----------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------- |
| **Separate Chaining** | Puts both items in the same spot using a Linked List. | Never runs out of space. Easy to delete.          | Uses extra memory for the Linked List pointers.                |
| **Linear Probing**    | Checks the very next spot (step by 1).                | Very cache-friendly (fast for computers to read). | Causes massive "traffic jams" (clustering).                    |
| **Quadratic Probing** | Jumps by squares (1, 4, 9...).                        | Reduces traffic jams.                             | Can still get stuck in loops if the lot gets too full.         |
| **Double Hashing**    | Uses a 2nd math formula to decide the jump size.      | Best distribution. No clustering.                 | Slightly slower because it has to calculate two math formulas. |
